一、最小可运行的 pgvector 检索示例（Python）

这是 RAG「召回阶段」的端到端最小实现：建表 → 写入权威片段+向量 → 混合检索（向量相似度 + 关键词过滤）。与 schema-and-rag.html 中的 content_chunk 表对齐。

维度必须一致：向量列维度（本例 512）须与所用嵌入模型输出维度完全一致，否则建表/插入会报错。生产环境可换用自托管中文模型或 OpenAI 兼容接口，VECTOR(n) 的 n 同步调整即可。
""" 最小可运行：基于 pgvector 的权威内容检索（RAG 召回阶段） 依赖: pip install psycopg2-binary pgvector sentence-transformers 说明: 向量维度须与所用嵌入模型一致；此处用多语模型 512 维。 """ import psycopg2 from pgvector.psycopg2 import register_vector from sentence_transformers import SentenceTransformer # 1) 连接（改为你的数据库；密码勿硬编码到生产） conn = psycopg2.connect( host="localhost", port=5432, dbname="faith_app", user="app", password="CHANGE_ME" ) cur = conn.cursor() register_vector(conn) # 2) 建表（与 schema 对齐；维度按模型调整） cur.execute("CREATE EXTENSION IF NOT EXISTS vector;") cur.execute(""" CREATE TABLE IF NOT EXISTS content_chunk ( chunk_id BIGSERIAL PRIMARY KEY, source_type VARCHAR(12) NOT NULL, -- bible / egw / doctrine source_id VARCHAR(32) NOT NULL, lang VARCHAR(4) NOT NULL, -- en / zh content TEXT NOT NULL, embedding VECTOR(512) ); """) conn.commit() # 3) 嵌入模型（多语，含中文；可换自托管模型） model = SentenceTransformer("BAAI/bge-small-zh-v1.5") # 输出 512 维 def embed(text: str) -> list: return model.encode(text, normalize_embeddings=True).tolist() # 4) 写入样例（真实项目由内容管线批量导入，且只来自权威原文） samples = [ ("bible", "GEN.1.29", "en", "And God said, Behold, I have given you every herb bearing seed..."), ("bible", "GEN.1.29", "zh", "神说，看哪，我将遍地上一切结种子的菜蔬……都赐给你们作食物。"), ("egw", "MH.1.3", "en", "Pure water is one of heaven's best gifts to man."), ] for st, sid, lang, txt in samples: cur.execute( "INSERT INTO content_chunk(source_type,source_id,lang,content,embedding) " "VALUES (%s,%s,%s,%s,%s)", (st, sid, lang, txt, embed(txt)), ) conn.commit() # 5) 混合检索：向量召回 + 关键词过滤（ILIKE 占位，生产可换 tsvector） def search(query: str, top_k: int = 5, kw: str = None): q_vec = embed(query) sql = """ SELECT source_type, source_id, lang, content, 1 - (embedding <=> %s::vector) AS score FROM content_chunk WHERE (%s IS NULL OR content ILIKE %s) ORDER BY embedding <=> %s::vector LIMIT %s """ cur.execute(sql, (q_vec, kw, f"%{kw}%" if kw else None, q_vec, top_k)) return cur.fetchall() # 6) 调用示例 for row in search("饮食与健康有什么教导", top_k=3): print(f"[{row[0]}:{row[1]}/{row[2]}] score={row[4]:.3f} {row[3][:40]}") cur.close(); conn.close()

上线前要点

  • 只索引权威原文：content_chunk 的 content 来源只能是 KJV / EGW 原版 / 教义英文（或本应用已审中文），绝不混入和合本或译本。
  • 混合检索：向量负责语义召回，关键词（建议升级为 tsvector 全文）负责精确命中专有名词（Sabbath、sanctification 等）。
  • 重排 + 阈值：召回后按 score 阈值（如 0.72）过滤，低于则判定"无足够权威依据"，转人工（见 RAG 时序图闸门）。
  • 结果回写引用：检索命中的 source_type+source_id 即作为 qa_citation 的溯源锚点，前端可一键展开原文。

二、对照注释（comparison_note）撰写规范

comparison_note 是模块 A "指出差异" 的落地产物。其定位是客观释经观察，不是论战。规范强制"对事不对人、引用原文依据、结论中性"。

2.1 必填字段（与表结构对应）

字段含义要求
verse_refKJV 书卷 章:节如 GEN.1.29
kjv_textKJV 英文原句逐字引用，不得改写
our_zh本应用译法来自 bible_verse_zh（已审）
cuv_text和合本译法仅作参照对象展示
diff_type差异类型wording / structure / theology / archaism
observation差异客观描述只陈述"X 译作 A，Y 译作 B"
basis原文依据词形 / 语法 / 上下文，须注明
implication理解影响（可选）中性陈述，不升级为指责
conclusion一句话归纳对事不对人
author / status作者 / 状态须 theologian 审核 approved 才发布

2.2 语气红线（撰写守则）

  • ✅ 写"KJV 此处用词 X，和合本作 Y，差异在于……"，不写"和合本错了 / 翻译失败"。
  • ✅ 同样要标注 KJV 自身的古旧用法（如 charity=爱、conversation=为人），体现学术诚实，不单向批评。
  • ✅ 任何差异结论须有 原文词形 / 语法 / 语境 支撑，可核查。
  • ❌ 禁止人身化、禁止教派攻击、禁止"唯有本应用正确"之类绝对化表述。
  • ❌ 禁止把神学立场分歧包装成"翻译错误"（立场 ≠ 误译）。

2.3 样例（撰写范式演示，非发布内容，须经神学顾问审）

样例 A · 用词差异（展示双向诚实）

verse_ref：1CO.13.13（KJV）

kjv_text："And now abideth faith, hope, charity, these three; but the greatest of these is charity."

our_zh："如今常存的有信、有望、有爱，这三样；其中最大的是爱。"

cuv_text（参照）："如今常存的有信，有望，有爱；这三样，其中最大的是爱。"

diff_type：archaism（KJV 古旧词）+ wording

observation：KJV 用 "charity" 译 ἀγάπη；和合本用"爱"。本应用依 1611 语境（charity 当时即"基督教之爱"）译作"爱"，与和合本一致。

basis：ἀγάπη 在 KJV 时代 "charity" 含"神圣之爱"义；现代英语该义已窄化，故重译。

conclusion：此处和合本译法准确；差异源于 KJV 古词，本应用据语境重译，三方在"爱"上实质一致。

样例 B · 结构 / 措辞差异（中性指出）

verse_ref：PHI.3.20（KJV）

kjv_text："For our conversation is in heaven; from whence also we look for the Saviour..."

our_zh："我们却是天上的国民；并且等候救主……"

cuv_text（参照）："我们却是天上的国民；并且等候救主……"

diff_type：archaism（KJV "conversation"= citizenship/behavior）

observation：KJV "conversation" 在 1611 指"公民身份 / 行事"，现代已变为"交谈"；和合本与本项目均据原意译作"国民 / 天上的国籍"。

basis：πολίτευμα（politeuma）本义" citizenship / 政体"，KJV 借古英语 conversation 表"居留与身份"。

conclusion：和合本此处准确把握原意；本应用译文与之相同，差异仅存在于 KJV 古词与现代理解之间。

说明：上面两例刻意选取"和合本译法准确、差异在 KJV 古词"的情形，用以示范规范的"双向诚实"原则——避免把对照功能变成单向批评。真正需要标注"和合本偏离"的条目，须由神学顾问基于 basis 提供可核查的原文依据后撰写，绝不由模型自由生成。

2.4 与校验机制衔接

  • 每条 comparison_note 入库即进入 review_queue，状态 pending，approved 前不展示。
  • 自动化检查：observation 不得含黑名单词（"错误/失败/异端"等绝对化词触发人工复核）；basis 必填。
  • 版本化：修改即写 content_version，可回滚。
